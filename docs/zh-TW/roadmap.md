# 路線圖

[English](../en/roadmap.md)

MVP 已端對端證明了整個工作流程。以下是接下來的步驟，依優先順序排列。每一項都是可以專注完成的一份工作。

## 接下來

1. **擴大 Live AI 的評估。** 六個範例已對真實 API 執行過（見[評估](evaluation.md#live-ai模型呼叫延遲與成本)）。下一步：兩種語言各 10–20 個自己的構想、其他請求，以及在同樣的流程上比較用較便宜的模型做請求分析。
2. **在真實硬體上量測。** 在有 GPU 的桌機上執行 `BENCH_GPU=1 pnpm bench:browser`，在中階手機上看應用程式內的回顧，並公布數據（見[評估](evaluation.md#真實硬體)）。自適應畫質已完成；有了真實數據後，門檻可能需要調整。

## 之後

- **更多有真實規則的協商情境：** 為整體色盤變暖與放慢速度建立規則，以及段落層級的速度或長度修改。（更溫暖的結尾、更混亂、加快速度已經有規則。）
- **美術指導，下一步：** 依段落類型的鏡頭語言、依情緒的配色，以及讓低畫質在慢速裝置上也關掉光束。（0.1.0 之後已完成第一版：依段落類型的燈光、空氣感與動態。）
- **聲音，下一步：** 依情緒的樂器，以及在真實喇叭上量測過的混音。（0.1.0 之後已加入每種段落類型各自的聲部。）
- **分享：** 匯出與匯入 score；演出的唯讀連結。
- **無障礙稽核：** 與螢幕閱讀器使用者一起進行；為演出提供字幕或口述影像。
- **瀏覽器覆蓋：** 在 CI 中加入 Firefox 與 Safari。

## 不在計畫中

- Score 中的可執行內容（來自模型的腳本或 shader）。Score 只會是資料。見[設計決策](design-decisions.md)。
- 頻閃效果。2 Hz 上限是安全規則，不是設定。
