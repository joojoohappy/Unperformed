# 設計決策

[English](../en/design-decisions.md)

塑造 UNPERFORMED 的決策紀錄。每則說明決定了什麼、為什麼，以及代價。

## ADR-001：模型寫 Interpretation，程式碼寫 Score

**決定。** 規劃者（示範規則或模型）產出小而偏創意的 `Interpretation`，再由確定性編譯器轉成完整的 `PerformanceScore`。

**原因。** 模型擅長意圖與語言，在拍數計算與一致的數值範圍上不可靠。編譯器能保證段落連續、範圍有效與安全上限，並讓示範模式與 Live AI 有相同的保證。

**代價。** 模型無法表達編譯器不認識的東西。要擴充表現範圍，需要擴充 schema 與編譯器，而不是 prompt。

## ADR-002：權限由程式碼執行，而非 prompt

**決定。** 對 score 的每個修改都是 typed patch。`applyPatch` 為每個操作分類（`ai`、`shared`、`human`），並拒絕行為者無權做的事。已核准的限制條件約束所有行為者，包括人，直到人明確解除它為止。

**原因。** Prompt 可以要求模型遵守界線，但無法保證；測試可以。

**代價。** 每種新的編輯類型都需要權限規則與測試。

## ADR-003：分歧必須有規則作為根據

**決定。** 在高潮情境中，只有當進入高潮時舞台能量已達 60% 以上，導演才會反對。模型可以撰寫反對的說法、調整壓抑拍數，但無法製造規則不支持的反對。

**原因。** 為了顯得有自主性而反對的 AI 合作者，只會浪費人的時間。可測試的理由（爆炸沒有可以對比的東西）讓反對保持誠實。

**代價。** 反對只限於有規則的情境。協定是通用的，但目前只有高潮情境有完整的規則。

## ADR-004：音訊時鐘是主時鐘

**決定。** 視覺在每個影格向 transport 詢問目前的 beat。有聲音時，beat 來自 `AudioContext.currentTime`。

**原因。** 音訊掉格一定聽得出來，視覺掉格則較不明顯。以音訊時鐘驅動視覺，即使渲染變慢也能保持同步。

**代價。** 聲音關閉或被阻擋時改用 `performance.now()` 時鐘，此時沒有音訊，也就沒有同步可言。

## ADR-005：時間軸是純函式

**決定。** `sample(score, beat, options)` 回傳舞台在那一瞬間需要的一切，不保留任何狀態。

**原因。** 拖動時間軸、排練、減少動態效果、介入、逐格擷取影片、閃光檢查與測試，全都使用同一個函式。重播在設計上就保證相同（`timelineFingerprint`）。

**代價。** 需要歷史的效果（拖尾、物理）必須由 beat 推導，或作為只存在於渲染器的修飾。

## ADR-006：一切都是程序化生成

**決定。** 幾何、燈光與聲音都在執行時生成。不使用取樣音檔、貼圖或第三方媒體。

**原因。** 沒有素材授權問題、bundle 小，而且 score 完全決定看到與聽到的內容。

**代價。** 美學範圍比使用素材庫更窄。

## ADR-007：示範模式是一級功能，且清楚標示

**決定。** 整個工作流程不需任何憑證，即可用確定性規則跑完。每則訊息都顯示來源：`示範規則（未使用 AI 模型）`、`規則備援`，或模型 id。

**原因。** 任何人都能試用，CI 能端對端測試，也沒有人會誤以為規則是模型。

**代價。** 示範規劃者理解的詞彙有限（見[已知限制](limitations.md)）。

## ADR-008：API key 留在伺服器端

**決定。** Live AI 經由 `services/ai`。瀏覽器呼叫 `/api/*`（開發時由 Vite proxy 轉送），永遠看不到 key。

**原因。** 任何放進前端 bundle 的 key 都等於公開。

**代價。** Live AI 需要一個執行中的服務。靜態部署（例如 GitHub Pages）只能提供示範模式。

## ADR-009：2D 備援渲染器與形態替代鏈

**決定。** 沒有 WebGL 時，由 Canvas2D 渲染器繪製同一份 layout。它無法繪製的形態，會依固定的替代鏈替換（`lattice → grid` 等）。

**原因。** 演出應該在低階或受限的裝置上也能執行，而不是直接失敗。

**代價。** 2D 舞台較平面，也沒有光照模型。

## ADR-010：安全上限寫在引擎裡

**決定。** 無論 score 怎麼寫，時間軸都把燈光調變限制在 2 Hz 與 30% 深度。系統的減少動態效果設定與介面開關都會被遵守。

**原因。** 光敏安全不能依賴模型或人把數字設對。

**代價。** 舞台在設計上就無法頻閃。
