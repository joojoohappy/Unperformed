# 已知限制

[English](../en/limitations.md)

誠實列出 UNPERFORMED 目前還做不到、或尚未驗證能做到的事。

## Live AI

- **尚未以真實 API 驗證。** 服務是在沒有 API key 的情況下開發與測試的。測試以記憶體內的假 transport 取代 HTTP：它們證明了請求格式、驗證、重試、錯誤對應與用量計算，但無法證明真實模型回答的創作品質，也無法得知真實的延遲與成本。量測方法見[評估](evaluation.md)。
- 成本估計使用 `services/ai/src/unperformed_ai/config.py` 中的靜態價格表。
- Live AI 需要服務在執行中。靜態部署只能提供示範模式。

## 示範模式

- 規則規劃者能辨識的英文與繁體中文詞彙有限（秩序、崩解、混亂、寂靜、黎明、流動等）。無法辨識的構想會套用一般的四段式結構，編排階段會明確說明。
- 協商理解八種請求：高潮爆炸、大聲的結尾、頻閃或閃光、更溫暖的色彩、更溫暖的結尾、更多混亂、加快與放慢。其他請求會得到「無法理解」，且不會有任何改變。
- 四個情境有創作分歧規則：高潮、更溫暖的結尾、崩解段落更混亂、加快速度（見[協商協定](negotiation-protocol.md#有規則的情境)）。其他請求只會是限制條件衝突、安全提示或同意。
- Live AI 把請求分類為新類型的部分，只在模擬的服務上測試過，尚未以真實模型執行。

## 渲染與音訊

- 只在使用 SwiftShader（軟體 WebGL）的 headless Chromium 中量測過。尚未在有 GPU 的瀏覽器、Firefox 或 Safari 上量測。Safari 與 Firefox 尚未測試。
- 自適應畫質只有一個低畫質等級，而且只會往下切換。20 ms 的門檻尚未在真實裝置上調整過。
- 3D 舞台是由 240 個元素組成的單一 instanced mesh，搭配簡單的光源。風格刻意克制，尚未針對各段落做美術指導。
- 2D 備援沒有光照模型，只繪製平面投影。
- 聲音由振盪器與濾波噪音合成，音色簡單。
- three.js 改為按需載入，但仍是每個舞台畫面都需要的 471 KB chunk（gzip 後 119 KB）；它載入完成之前舞台無法渲染。

## 安全與無障礙

- 閃光檢查是從取樣時間軸中的主光顏色與強度估算亮度，並非量測實際渲染的像素。無論如何，引擎都把調變限制在 2 Hz 與 30% 深度。
- 介面可用鍵盤操作、有標籤，也遵守減少動態效果的偏好，但尚未與螢幕閱讀器使用者一起進行稽核。

## 產品

- 一個人、一個瀏覽器。Session 存在 `localStorage`：沒有帳號、分享或伺服器端保存。匯出是下載 JSON。
- 繁體中文介面與文件是與英文版同時撰寫的，尚未經過母語編輯審閱。

## 媒體

- 由於軟體 WebGL 無法即時渲染，示範影片是以虛擬時鐘逐格擷取的。詳見[媒體](media.md)。
