# Media: how it was made and how it is licensed

[繁體中文](../zh-TW/media.md)

Every image and video in [`assets/demo/`](../../assets/demo) was captured from
the running studio by [`scripts/capture-media.mjs`](../../scripts/capture-media.mjs).
None of it is drawn, mocked up or generated by an image model. You can
regenerate all of it with `pnpm media`.

## Environment

Headless Chromium (Playwright) on a 4-core Linux container with no GPU. WebGL
is rendered on the CPU by SwiftShader. The studio is served by the Vite dev
server.

## How the video was made

Software WebGL cannot render this stage in real time (about 10 fps measured, see
[evaluation](evaluation.md)). Recording the screen in real time would have
produced a choppy video that misrepresents the app in either direction. So:

1. **Interface steps** (typing, clicking, choosing) are screenshots of the real
   interface, each held for a set time.
2. **The performance** is captured frame by frame. Playwright's virtual clock
   is paused, advanced by exactly 1/30 s, and the stage is screenshotted. Each
   frame shows exactly what the app renders at that point in the timeline. The
   person's blackout is pressed with the keyboard during the capture, as a user
   would.
3. **Sound** is rendered by the app's own audio engine
   (`renderOffline` in `apps/web/src/audio/engine.ts`) from the same score,
   then muxed in. During the blackout the same gain change the app applies
   (0.25 instead of 0.9) is applied to the track.
4. **The frame-rate readouts are hidden in the video only**, because a rate
   measured under a virtual clock is meaningless. The screenshots show the real
   measured rate.
5. Captions are burned in below the app (English and Traditional Chinese), and
   also shipped as separate SRT and WebVTT files.
